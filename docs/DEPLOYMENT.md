# راهنمای استقرار روی هاست اشتراکی

این راهنما مراحل استقرار بردار روی یک هاست اشتراکی PHP معمولی (cPanel یا مشابه، بدون دسترسی SSH کامل الزامی) را پوشش می‌دهد. پلتفرم بدون فریم‌ورک سنگین و بدون وابستگی به سرویس‌های خارجی (به‌جز درگاه پرداخت و SMTP اختیاری) ساخته شده تا با محدودیت‌های هاست اشتراکی سازگار باشد.

## ۱. پیش‌نیازهای هاست

- PHP 8.1 یا بالاتر با افزونه‌های `pdo_mysql`, `mbstring`, `openssl`, `json` (این‌ها در اکثر هاست‌های اشتراکی به‌صورت پیش‌فرض فعال‌اند)
- دیتابیس MySQL 8.x یا MariaDB 10.11+ (اکثر هاست‌های اشتراکی MariaDB ارائه می‌دهند)
- امکان تنظیم **Document Root روی پوشه `public/`** (در cPanel: «Domains» → «Document Root»، یا در صورت نبود این امکان، بخش «آپلود فایل‌ها در ریشه دامنه» را در پایین همین سند ببینید)
- دسترسی SSH یا File Manager برای اجرای `composer install` و migration (اگر SSH موجود نیست، از بخش «نصب بدون SSH» استفاده کنید)

## ۲. آپلود فایل‌ها

کل مخزن (به‌جز `.git/`, `vendor/`, `.env`) را روی هاست آپلود کنید. اگر Document Root قابل تغییر به `public/` است:

```
/home/username/bordar/           ← ریشه پروژه (بیرون از دسترس عمومی وب)
    public/                       ← این پوشه باید Document Root شود
    src/
    vendor/
    ...
```

اگر هاست **اجازه تغییر Document Root را نمی‌دهد** (برخی پلن‌های ارزان‌قیمت)، باید محتویات `public/` را در ریشه دامنه (`public_html/`) قرار دهید و بقیه پروژه (`src/`, `vendor/`, `.env`, ...) را **یک سطح بالاتر، خارج از `public_html/`** آپلود کنید؛ سپس مسیر `require` در `public_html/index.php` را متناسب با مسیر واقعی روی سرور اصلاح کنید. **هرگز** `src/`, `.env`, یا `vendor/` را داخل `public_html/` قرار ندهید — این پوشه‌ها حاوی کلید رمزنگاری، اطلاعات دیتابیس و منطق برنامه هستند.

## ۳. نصب وابستگی‌ها

با SSH:

```bash
composer install --no-dev --optimize-autoloader
```

بدون SSH: `composer install --no-dev` را روی یک ماشین محلی با همان نسخه PHP اجرا کنید و پوشه `vendor/` تولیدشده را همراه بقیه فایل‌ها آپلود کنید.

## ۴. پیکربندی `.env`

`.env.example` را به `.env` کپی و مقادیر زیر را **الزاماً** تنظیم کنید (جدول کامل متغیرها در [`README.md`](../README.md#پیکربندی-env)):

- `APP_ENV=production`
- `APP_DEBUG=false` — در production باید همیشه خاموش باشد تا پیام خطای داخلی/Stack trace به کاربر نمایش داده نشود
- `APP_URL` — آدرس واقعی دامنه با `https://`
- `APP_KEY` — یک مقدار تصادفی قوی تولید کنید و **قبل از اولین آپلود فایل واقعی** تنظیم کنید (تغییر آن پس از آپلود فایل، فایل‌های رمزنگاری‌شده موجود را غیرقابل بازیابی می‌کند):
  ```bash
  php -r "echo 'base64:' . base64_encode(random_bytes(32)) . PHP_EOL;"
  ```
- `DB_*` — اطلاعات دیتابیس MySQL/MariaDB واقعی هاست
- `STORAGE_PATH` — یک مسیر **خارج از `public_html/`** با دسترسی نوشتن برای کاربر PHP (مثلاً `/home/username/bordar-storage`)
- `MAIL_*` — اطلاعات SMTP واقعی هاست یا سرویس ایمیل خارجی؛ در نبود این مقادیر ایمیل‌ها فقط در فایل نوشته می‌شوند و برای کاربر واقعی ارسال نمی‌شوند
- `ZARINPAL_MERCHANT_ID` — Merchant ID واقعی از پنل زرین‌پال
- `ZARINPAL_SANDBOX=false` — **الزامی** برای پرداخت واقعی؛ در sandbox هیچ تراکنش واقعی ثبت نمی‌شود
- `SMS_API_KEY`, `SMS_SENDER` — در صورت نیاز به پیامک واقعی
- `ADMIN_SEED_EMAIL`, `ADMIN_SEED_PASSWORD` — ایمیل/رمز ادمین اولیه؛ رمز پیش‌فرض نمونه (`Admin@12345`) **هرگز** نباید در production استفاده شود

## ۵. اجرای Migration و Seed

```bash
php src/Database/migrate.php
php src/Database/Seeders/run.php
```

پس از seed، بلافاصله وارد شوید و رمز ادمین را از پنل کاربری تغییر دهید (یا از ابتدا `ADMIN_SEED_PASSWORD` را در `.env` به مقدار قوی تنظیم کرده باشید).

## ۶. بررسی امنیتی پس از استقرار

- تایید کنید فایل `.env` از طریق مرورگر قابل دسترسی نیست (`https://yourdomain.com/.env` باید ۴۰۳/۴۰۴ برگرداند) — قانون `<FilesMatch>` در `public/.htaccess` این را پوشش می‌دهد، اما اگر `.env` بیرون از `public/` قرار دارد (که باید همین‌طور باشد) این نگرانی اصلاً مطرح نیست
- تایید کنید `STORAGE_PATH` از طریق URL مستقیم قابل دسترسی نیست
- تایید کنید `APP_DEBUG=false` است (یک خطای عمدی مثل درخواست یک مسیر نامعتبر نباید Stack trace نمایش دهد)
- ورود ادمین را تست کنید و مطمئن شوید مرحله 2FA اجباری است
- گواهی HTTPS/SSL دامنه را فعال کنید (اکثر هاست‌های اشتراکی Let's Encrypt رایگان ارائه می‌دهند) — کوکی‌های session با پرچم `Secure` روی HTTPS به‌درستی کار می‌کنند

## ۷. محدودیت‌های شناخته‌شده هاست اشتراکی

- این پروژه از هیچ Queue/Worker پس‌زمینه استفاده نمی‌کند (ایمیل/پیامک به‌صورت همزمان در همان درخواست HTTP ارسال می‌شوند)؛ در صورت نیاز به مقیاس بالاتر، ارسال اعلان‌ها باید به یک صف واقعی منتقل شود.
- هیچ Cron Job‌ای برای این نسخه لازم نیست؛ تمام منطق (انقضای لینک دانلود، محدودسازی نرخ ورود) در زمان درخواست محاسبه می‌شود، نه با یک job زمان‌بندی‌شده.
- حجم آپلود فایل توسط تنظیمات PHP هاست (`upload_max_filesize`, `post_max_size`) محدود می‌شود؛ در صورت نیاز این مقادیر را در `php.ini` هاست یا فایل `.user.ini` (در صورت پشتیبانی هاست) افزایش دهید.
